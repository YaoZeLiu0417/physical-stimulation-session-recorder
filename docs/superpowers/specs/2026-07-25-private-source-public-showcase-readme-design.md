# 私有源码与公开展示 README 设计

## 1. 目标

为 **Physical Stimulation Session Recorder（物理刺激干预记录工具）** 建立两层发布结构：

- 研究团队在私有仓库中维护完整应用、问卷逻辑与开发历史。
- 崔再续老师课题组可通过公开展示仓库查看脱敏 README，并通过受控入口体验网页。
- 公开材料不披露尚未公开的研究设计、测量内容、评分规则、源码或真实数据。

本次交付包含新版应用代码的私有发布、可见文案中性化、公开展示 README、合成视觉资源和受控演示入口。

## 2. 已确认的命名

### 产品显示名

- 英文：`Physical Stimulation Session Recorder`
- 中文：`物理刺激干预记录工具`

### 仓库名

- 私有源码仓库：`physical-stimulation-session-recorder`
- 公开展示仓库：`physical-stimulation-session-recorder-showcase`

公开页面、README、图片替代文本、仓库描述和演示入口均不使用旧研究名称或其缩写。

## 3. 双仓库架构

### 3.1 私有源码仓库

现有源码仓库先改为私有，再改为中性名称。它保留完整 Git 历史，并接收已完成的问卷流程、数据可靠性和风险提示改造。

私有仓库可包含：

- 应用源码与测试；
- 内部问卷定义与计分实现；
- 部署配置模板和运维文档；
- 内部设计与实现计划。

私有仓库仍不得提交真实凭据、真实受试者数据、外层研究资料工作区中的协议 PDF、问卷 Excel 或分析输出。

### 3.2 公开展示仓库

公开展示仓库从空仓库初始化，不复用私有仓库的 Git 历史。首版仅包含：

- `README.md`；
- `assets/` 下经审核的合成图片；
- 必要的非敏感仓库元数据。

公开展示仓库不包含源码、测试、配置、内部文档、部署工作流、问卷定义或研究资料。

### 3.3 演示网页

演示网页从私有源码仓库部署。公开 README 可以包含演示链接，但不得在 URL 中嵌入参与者编号、签名参数、访问令牌或其他秘密。访问密码或一次性访问方式通过独立渠道提供给目标课题组。

公开仓库、演示部署和私有源码仓库之间没有自动同步研究内容的流水线。公开资产必须经过单独脱敏审核后手工发布。

## 4. README 信息架构

README 采用中文为主、英文摘要补充的结构：

1. 中性产品名与一句中文定位；
2. 简短英文摘要；
3. 隐私、合成演示和技术框架标签；
4. “打开受控演示”主入口；
5. 一张合成主界面预览；
6. 三项核心能力：安全进入、分步记录、可靠保存；
7. 四步体验流程：进入、记录、反馈、确认；
8. 明确的公开边界；
9. 演示访问说明；
10. 简短联系说明。

公开展示仓库没有可运行源码，因此 README 不提供安装、部署、配置或问卷维护说明，也不展示测试实现细节。

## 5. 视觉设计

README 使用“产品优先”布局：标题、简述、演示入口和主图位于首屏，老师打开仓库后应在十秒内理解工具用途并找到体验入口。

视觉语言参考 Alto Neuroscience 的信息层级，但不复制其标志、插图或品牌素材：

- 主画布为白色；
- 正文和标题使用深靛蓝 `#000035`；
- 大区块和结构强调使用紫色 `#2D2674`；
- 主行动按钮使用洋红 `#DD1D86`；
- 少量状态提示使用天蓝 `#33B0E4` 和浅橙 `#FFBC7D`；
- 辅助背景使用浅灰 `#F4F4F4`；
- 不使用绿色主视觉、渐变、品牌标志或装饰性光斑。

排版保持充足留白、清晰标题层级和紧凑正文。图片在桌面和移动端均不得产生文字溢出或遮挡。

## 6. 合成截图规则

公开图片必须专门制作，不能直接截取真实问卷或生产记录。截图可以演示：

- 中性的会话进度；
- 合成的会话反馈题；
- 通用滑动或选择控件；
- 成功保存和完成状态。

截图不得出现：

- 研究名称、刺激部位、干预参数或治疗机制；
- 量表名称、题目原文、测量时间表或评分规则；
- 真实或可关联的受试者编号；
- 真实日期、远程路径、上传响应、密钥或内部联系人；
- 生产环境 URL、浏览器签名参数或本地绝对路径。

图片文件名和替代文本也必须遵守同一边界。

## 7. 应用可见文案中性化

私有应用的页面标题、登录页标题、参与者页标题和管理员可见产品名统一改为中性产品名。内部数据字段、记录 schema、访问签名格式和已持久化记录结构保持不变，避免文案调整造成数据迁移或兼容性风险。

问卷内容和研究逻辑不因公开 README 项目而改变。受试者仍看不到分数、风险标签、远程路径、原始上传响应、历史记录或运维信息。

## 8. 隐私门槛与发布顺序

发布顺序固定为：

1. 核对本地分支和远程仓库所有权；
2. 将现有源码仓库转为私有；
3. 将私有源码仓库改为中性名称；
4. 更新本地远程地址并验证私有可见性；
5. 在功能分支整合新版代码和可见文案调整；
6. 运行测试并通过私有仓库 PR 合并；
7. 新建无历史的公开展示仓库；
8. 添加经审核的 README 和合成资产；
9. 执行敏感词、链接、图片和仓库内容检查；
10. 推送公开展示仓库并验证匿名访问效果。

在步骤 2 和步骤 4 完成前，禁止把新版源码分支推送到现有公开仓库。公开展示仓库不得从私有源码仓库 fork，也不得复制 `.git` 历史。

## 9. 失败处理

- 仓库转私有失败：停止后续远程操作，不推送新版源码。
- 仓库改名失败：保留已经完成的私有状态，报告错误并等待处理。
- 本地分支整合失败：保留原分支与提交，不强推、不覆盖远程主分支。
- 测试失败：不创建合并 PR，不发布演示更新。
- 敏感扫描或图片审核失败：不推送公开展示仓库，修订后重新完整检查。
- 演示链接不可达或访问控制失效：从 README 移除入口，修复后再发布。

所有失败路径都不删除旧仓库、不重写共享历史，也不扩大公开范围。

## 10. 验证方案

### 私有源码

- 运行现有完整自动化测试；
- 检查可见文案不再显示旧研究名称；
- 验证内部字段、记录 schema 和上传流程没有因改名变化；
- 验证仓库可见性为 `private`，远程地址指向中性名称。

### 公开展示

- 对全部文本、文件名和图片替代文本执行不区分大小写的敏感词扫描；
- 确认没有量表名称、题目、评分、受试者标识、凭据、本地路径和生产 URL；
- 检查 README 内部链接和受控演示链接；
- 在桌面和移动端检查图片清晰度、尺寸和文字可读性；
- 使用未登录访问验证公开仓库只包含允许的展示材料；
- 人工复核合成截图，不依赖自动扫描替代视觉审核。

### 回归标准

新版源码当前完整测试基线为 `302 passed, 3 skipped`；跳过项为 Windows 符号链接权限场景。整合与中性化修改后的结果不得低于该基线，除非新增测试使总数上升。

## 11. 非目标

- 不公开完整源码或问卷内容；
- 不公开研究方案、测量时间表或评分规则；
- 不把研究资料工作区纳入 Git；
- 不在本轮重构内部记录 schema；
- 不在本轮重新设计问卷内容；
- 不保证清除旧公开仓库曾被第三方克隆或缓存的副本。

## 12. 完成标准

满足以下全部条件才算完成：

- 私有源码仓库使用中性名称并包含经过测试的新版代码；
- 应用可见区域不显示旧研究名称；
- 公开展示仓库为独立、无私有历史的新仓库；
- README 符合已确认的双语、产品优先和 Alto 风格；
- 所有公开截图均为合成内容并通过人工隐私复核；
- 老师可以打开公开 README，并通过独立提供的访问方式体验受控网页；
- 公开仓库中不存在研究内容、源码、真实数据、凭据或内部路径。
