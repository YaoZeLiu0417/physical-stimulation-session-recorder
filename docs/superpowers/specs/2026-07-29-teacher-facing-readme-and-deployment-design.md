# Teacher-Facing README And Deployment Design

**Date:** 2026-07-29  
**Status:** Approved design  
**Audience:** 崔再续老师及需要快速了解研究工具、操作闭环和数据边界的项目评审者

## Goal

将已完成的六阶段 Streamlit 应用与 GitHub README 同步更新，使首次访问者无需阅读实现细节，也能快速理解：

1. 这是一个面向居家物理刺激干预研究的受控会话工具；
2. 应用按六个阶段完成进入、状态确认、本地录制、结构化作答、本地导出和完成确认；
3. 录制媒体保存在浏览器本地，问卷资料包由用户下载到本地；
4. Stage 04、05、06 已形成清晰、完整且相互对齐的操作闭环；
5. 项目具有可复现的测试、部署和隐私边界。

README 使用中文主线、英文辅助。首要目标是研究汇报，不采用营销落地页结构。

## Approved Direction

采用草图方案 A“研究汇报型”，并吸收另外两套方案中有价值的部分：

- A 提供首屏研究定位、六阶段方法和关键边界；
- B 的大幅应用界面用于第二屏实际操作展示；
- C 的数据流图用于隐私与方法说明。

README 只保留一个正式应用入口：

`https://physical-stimulation-session-recorder-lqtdzyddneawgtmkzviryt.streamlit.app/`

该入口用于完整演示当前六阶段应用。README 不同时列出旧入口或备用入口，避免评审者进入不同版本。

## Streamlit Application Scope

应用部分沿用已确认并已通过回归测试的 Stage 04–06 实现：

- Stage 04 为开放式问卷画布，包含可访问进度、实际题目、原生作答控件和明确导航；
- Stage 05 显示本地 ZIP 文件摘要、JSON + Excel 内容、仅本地保存声明、下载按钮和保存确认门禁；
- Stage 06 显示完成状态、会话数据清理、媒体未上传到应用服务器和安全关闭提示；
- 左侧六阶段 rail 继续承担导航与当前位置表达；
- 不改变题目、选项、分支、评分、状态键、ZIP 字节、认证、录制器、会话清理或完成门禁。

本阶段不再发明新的应用功能。应用工作的剩余内容是将现有实现与 README 一起集成到 `main`，使 Streamlit 部署与 GitHub 展示同步。

## README Information Architecture

### 1. First Screen

README 首屏按以下顺序呈现：

1. 中文主标题“物理刺激干预会话伴侣”；
2. 英文副标题“Physical Stimulation Intervention Session Companion”；
3. 一句话研究定位；
4. 单一“打开完整演示”入口；
5. 三项核心事实：`06 阶段流程`、`本地录制与导出`、`无媒体上传路径`；
6. 六阶段动态流程图及静态回退图。

首屏避免大段部署说明、故障排查和实现术语。访问者应先理解研究工具，再决定是否继续阅读技术细节。

### 2. Actual Application Surfaces

第二部分标题为“实际界面与操作闭环”，按操作顺序展示：

1. Stage 03 本地录制；
2. Stage 04 分步结构化作答；
3. Stage 05 本地资料包；
4. Stage 06 完成确认。

Stage 04–06 使用三个并列、等高的实际页面视图。每个视图显示完整页面区域和当时可见的真实界面文字：

- Stage 04 展示一个代表性真实题目、实际选项、进度和导航；
- Stage 05 展示合成 ZIP 文件名、格式、内容、本地保存说明和操作按钮；
- Stage 06 展示真实完成与隐私确认文案。

展示真实界面不等于公开完整题库清单。README 只展示截图时可见的代表性题目，不另行列出所有问卷题目和选项。

### 3. Method And Data Boundary

数据流图清楚区分两个边界：

```text
摄像头 + 麦克风 -> Chrome 本地录制 -> WebM 本地保存
结构化作答 -> Streamlit 临时会话内存 -> JSON + Excel ZIP 本地下载
```

配套文案必须准确说明：

- 媒体字节没有上传到 Streamlit 的路径；
- 问卷值仅在活动会话中进入临时内存以生成本地资料包；
- 应用不把服务器作为持久录制或响应档案；
- 完成确认会清理当前会话中的敏感阶段状态。

### 4. Verification And Reproduction

README 用简洁证据说明测试覆盖：

- 六阶段门禁和状态清理；
- 问卷分支、必答检查和进度语义；
- 本地 ZIP 字节、文件名、MIME 和下载确认；
- 浏览器本地录制器状态机和无网络能力边界；
- README 资产、链接、尺寸和隐私文案合同。

Chrome 指南、故障排查、本地运行、Secrets 名称和验证命令保留在后半部分或折叠区。

## Visual Asset System

现有 `tools/generate_operational_readme_assets.py` 继续作为 README 图片的唯一生成来源，避免手工修改二进制资产后无法复现。

需要更新或新增的生成资产包括：

- 六阶段动态流程和静态回退；
- 本地录制页面；
- Stage 04–06 操作闭环组合图；
- 如组合图可读性不足，则生成 Stage 04、05、06 独立图，并在 README 中使用三列布局。

图片使用当前 Alto 配色、窄圆角、真实应用结构和稳定尺寸。禁止使用营销式渐变、装饰光球或与应用不一致的大面板。

所有截图数据必须为合成数据：

- 合成参与者标识；
- 合成日期和文件名；
- 不包含真实作答、真实导出文件或有效认证信息；
- 可显示代表性真实题目和实际 UI 文案。

## Error And Fallback Behavior

- GIF 无法播放时，README 提供静态流程图回退；
- 组合图在 GitHub 窄屏不可读时，改用纵向排列的独立图；
- 正式应用入口不可达时，不自动切换到旧版本 URL；应修复部署或 README 链接；
- 图片生成失败时，不提交部分更新；生成器和资产合同必须一起通过；
- 不把本地测试密码、Secrets、签名链接或真实数据写入 README 和资产。

## Test Contracts

实现需扩展现有 README 合同测试，至少验证：

- 首屏中文主标题与英文副标题存在；
- 只出现一个正式 Streamlit 应用入口，且 URL 精确；
- 六阶段名称和顺序完整；
- Stage 04、05、06 图片及说明存在；
- 本地录制、本地 ZIP、无媒体上传和临时会话边界表述存在；
- 生成资产清单、尺寸、格式和调色板符合约定；
- README、生成器和提交资产一致；
- 禁止密码、Secret 值、真实身份和本地绝对路径进入公开内容。

应用原有 Python、Node、编译和 diff 验证必须继续通过。

## Non-Goals

- 不把 README 改成营销主页；
- 不公开全部题库或全部量表内容；
- 不增加服务器端媒体上传或持久数据库；
- 不修改录制器、问卷评分和导出数据结构；
- 不在本阶段创建第二套展示应用；
- 不在未经验证的情况下直接推送 `main`。

## Acceptance Criteria

1. 崔老师打开仓库首屏后，可以在第一屏理解研究工具、六阶段流程和本地优先边界；
2. README 中的 Stage 04–06 与正式 Streamlit 应用视觉一致；
3. 正式入口只指向完整演示应用；
4. README 使用中文主线、英文辅助，技术细节不抢占主叙事；
5. 公开图片只使用合成数据，但保留代表性真实界面文字；
6. 所有 README、资产、应用和隐私合同测试通过；
7. 应用代码与 README 在同一已验证 HEAD 上集成到 `main`。
