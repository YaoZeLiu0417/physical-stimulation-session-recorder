# taVNS NSSI 密集问卷整合设计

## 1. 目标

在现有 taVNS 干预日志中加入适合密集纵向采集的 NSSI 问题，同时保留 CRF 正式量表的原始题意、时间窗和计分规则。

系统需要实现：

- 每个 taVNS 干预日最后一次刺激后完成一次简短的日级核心记录。
- NSSI 想法、行为或自杀想法阳性时，按回答展开必要追问。
- 干预第 7、14、21、28 天追加每周 NSSI 扩展问卷。
- 正式访视继续使用 CRF 规定的完整 NSSI 量表。
- 所有 NSSI 相关问题进入同一数据系统，但不同时间尺度的数据保持独立。
- 受试者只看到填写与完成状态，不看到量表得分、风险等级或临床解释。

## 2. 依据与测量边界

设计依据：

- `D:\proj_taVNS\【最终版】tavns protocol_v7.pdf`
  - 第 8 页：主要研究目标为减少基线至干预后 3 个月的 NSSI 行为发生次数。
  - 第 56 页：主要临床结果通过 DSHI-Y 六类自伤行为测量。
  - 第 57 页：NSSI 意念与自伤冲动定义。
  - 第 86-87 页：主要、次要和探索性分析边界。
  - 第 94 页：过去 24 小时自杀想法、NSSI 行为及抵抗信心的密集采集题。
  - 第 111-112 页：NSSI 相关量表计分规则。
- `D:\proj_taVNS\【0212】 taVNS-CRF.pdf`
  - 第 7-8 页：正式访视量表时间表。
  - 第 49-67 页：DSHI-Y、C-FASM、自伤意念、自伤冲动、未来 NSSI、停止意愿、SICQ、改变准备度、SISS 和 PSS 原始题目及计分。

主要结局仍由正式访视的 DSHI-Y 支持。每日实际次数属于密集纵向指标，不替代 DSHI-Y，也不在未修改统计分析计划的情况下被称为注册主要结局。

DSHI-Y 的频次档位是有序分类，不能换算为虚构的精确次数。每日问卷直接询问实际次数，两种变量分别保存和分析。

## 3. 采集方案

采用分层自适应采集。

| 层级 | 触发时间 | 内容 | 目标负担 |
| --- | --- | --- | --- |
| 日级核心 | 当天最后一次 taVNS 干预后，每日一条正式记录 | 5 个核心问题 | 无阳性事件时不超过 2 分钟 |
| 条件展开 | 日级核心出现阳性回答 | 想法频率与强度、行为类型与次数、事件功能与医疗处理 | 仅在需要时出现 |
| 每周扩展 | 干预第 7、14、21、28 天 | 冲动、未来可能性、停止意愿、SICQ、改变准备度 | 约 4-6 分钟 |
| 正式访视 | CRF 规定的基线、干预后及随访节点 | 完整 NSSI 量表组 | 保留 CRF 原始题目、时间窗与计分 |

每周扩展按干预日历触发，不按累计完成次数或星期触发。同一受试者同一干预日只触发一次。

同一天存在多次刺激时，刺激次数和每次刺激参数进入同一日记录；受试者只在当天最后一次刺激后填写一次日级问卷，不重复生成多份日级问卷。

## 4. 日级核心问题

所有日级问题都明确使用“过去 24 小时”或“此时此刻”的时间窗。日级版本是 EMA 指标，不冒充原始 CRF 量表。

### 4.1 核心问题

1. 过去 24 小时，是否出现过不想死但想故意伤害自己的想法？
2. 过去 24 小时，是否发生过不想死但故意伤害自己的行为？
3. 过去 24 小时，是否出现过自杀想法？
4. 此时此刻，想要伤害自己的冲动有多强烈？使用 0-10 滑动条，0 为“没有冲动”，10 为“极强”。
5. 此时此刻，对自己能抵抗住自伤冲动有多大信心？使用 0-7 滑动条，0 为“一点信心也没有”，7 为“非常有信心”。

前三题使用明确的是/否选择，不使用滑动条。

### 4.2 自伤想法阳性分支

当问题 1 回答“是”时追加：

- 过去 24 小时自伤想法频率，0-4 滑动评分，端点为“只有一次”和“几乎一直”。
- 过去 24 小时最强自伤想法强度，0-10 滑动评分，端点为“很弱”和“极强”。

这些字段单独保存，不相加为日级意念总分。

### 4.3 NSSI 行为阳性分支

当问题 2 回答“是”时，逐项记录以下行为的实际次数：

1. 割伤皮肤。
2. 烧伤或烫伤皮肤。
3. 严重抓挠至留下伤痕或流血。
4. 咬伤自己至皮肤破损。
5. 撞击头部或其他身体部位至出现瘀伤。
6. 捶打自己至出现瘀伤。
7. 其他 NSSI 行为及其实际次数。

至少一类行为的次数必须大于 0。系统计算六类标准行为与“其他”的当日实际总次数。

同时记录：

- 是否因本次行为需要医疗处理。
- 从 C-FASM 15 类动机中选择与本次事件相关的原因。
- 可选的触发情境和应对方式文字记录。

日级动机选择是事件级描述，不计算正式 C-FASM 总分或分量表分数。完整 C-FASM 仅在正式访视计分。

### 4.4 自杀想法阳性分支

当问题 3 回答“是”时追加过去 24 小时出现频率，使用 0-4 滑动评分，端点为“只有一次”和“几乎一直”。

答案写入独立的 `safety_signals` 字段。自动风险阈值、通知人员和临床处置流程不在本轮范围内；在下一轮风险响应设计完成前，页面至少提供固定的支持信息和研究团队联系入口。

## 5. 每周扩展问卷

在干预第 7、14、21、28 天完成日级核心与条件分支后，追加以下内容：

### 5.1 自伤冲动

- 过去一周想到伤害自己的时间：1-100 连续滑动评分。
- 过去一周抵制伤害自己的困难度：1-7 滑动评分。

两题分别保存，不生成未经 CRF 定义的合成总分。

### 5.2 未来可能性与停止意愿

- 未来 NSSI 可能性：0-4，分数越高表示可能性越大。
- 停止未来 NSSI 的愿望：0-4，分数越高表示停止意愿越强。

两项方向相反，不能合并。

### 5.3 SICQ

- 7 个条目均使用 0-4 评分。
- 第 7 题反向计分，计分值为 `4 - raw_item_7`。
- 总分为 7 个计分值之和，范围 0-28。
- 任一条目缺失时保留原始答案并标记 `incomplete`，不生成总分。

### 5.4 改变准备度

- 改变的重要性：1-10。
- 已经准备好采取行动：1-10。
- 对改变能力的信心：1-10。

三项分别保存，不生成总分。

## 6. 正式访视模式

正式访视按 CRF 访视表展示完整 NSSI 量表，包括：

- DSHI-Y 终生与过去一年六类行为频次。
- 完整 C-FASM。
- 自伤意念 6 题。
- 自伤冲动 2 题。
- 未来 NSSI 可能性。
- 停止未来 NSSI 的愿望。
- SICQ。
- 改变准备度。
- SISS。
- PSS。

正式量表保存 `instrument_id`、`instrument_version`、`time_window`、原始答案、计分答案、完整性与总分。正式量表文本和选项不得用日级 EMA 文案替代。

上述列表表示系统支持的正式 NSSI 量表集合，并不表示每个正式访视都展示全套。`questionnaire_specs.py` 必须按 CRF 访视表编码访视-量表映射；例如 V5 干预后 3 个月沿用 V4 干预后 1 个月量表，而其他访视只展示各自规定的量表。

## 7. 页面与交互

### 7.1 流程

受试者流程为：

1. 完成 taVNS 干预录像。
2. 完成今日安全与状态记录。
3. 根据阳性回答完成条件分支。
4. 在第 7、14、21、28 天完成本周问卷。
5. 检查并提交。

每屏聚焦一个核心问题。阳性追问在当前问题下方展开，不把受试者跳转到不相关页面。无阳性回答时，5 个核心问题后直接进入提交检查。

### 7.2 视觉方向

采用 Alto Neuroscience 官网风格作为视觉参考，但不复制其品牌资产：

- 字体方向：Adelle Sans 风格的人文无衬线字体，实际实现使用可合法部署的本地或系统字体回退。
- 顶部使用高对比黑色导航基底。
- 主体使用大面积纯白，正文使用接近黑色。
- 功能强调色：深紫 `#2D2674`、亮蓝 `#33B0E4`、洋红 `#DD1D86`、橙色 `#FF8D2A`。
- 洋红用于当前步骤、滑动条活动轨道和主要交互反馈。
- 紫、亮蓝、洋红与橙色只作为流程和状态强调，不做大面积渐变背景。
- 控件边角不超过 8px，页面不使用卡片嵌套。
- 桌面端可显示流程侧栏；移动端隐藏侧栏并保留顶部进度条。

### 7.3 滑动评分

- 连续或有序评分使用滑动条，二元问题使用是/否分段选择。
- 滑动条始终显示数值、最低端语义和最高端语义。
- 支持触摸、鼠标和键盘操作。
- 每道滑动评分必须由受试者主动确认，不能把默认位置自动写为有效答案。
- `questionnaire_ui.py` 维护独立的 `answered_field_ids`；只有滑动条触发 `on_change` 后才将字段标记为已作答，点击“继续”时拒绝未被主动确认的默认位置。
- 受试者完成后只看到提交结果，不看到量表分数或风险标签。

## 8. 代码边界

当前 `app.py` 同时承担准入、问卷、录像、转码、上传和运维界面。本功能只做服务于问卷可靠性的拆分：

- `app.py`：页面路由、会话流程和现有录像集成。
- `questionnaire_specs.py`：题目、选项、时间窗、访视与分支定义。
- `questionnaire_scoring.py`：纯函数计分与完整性判断。
- `record_store.py`：记录标识、草稿、修订、原子 JSON 写入和上传状态。
- `questionnaire_ui.py`：受试者问卷渲染、Alto 风格 CSS 和步骤控制。
- `tests/`：计分、分支、日历触发、持久化和上传集成测试。

不引入新的前端框架或数据库依赖。优先使用 Python 标准库与现有 Streamlit 组件。

## 9. 数据模型与持久化

### 9.1 记录标识

每次干预使用稳定的 `record_id`，由经过验证的受试者编号、干预日期和随机后缀组成。录像、问卷 JSON、上传状态和修订记录使用同一 `record_id`。

受试者编号必须通过允许字符校验，不能直接将任意输入拼接到本地或远端路径。

### 9.2 核心 JSON 字段

```json
{
  "schema_version": 4,
  "record_id": "sub-001_20260724_a1b2c3d4",
  "subject_id": "sub-001",
  "intervention_day": 7,
  "record_date": "2026-07-24",
  "revision": 1,
  "instrument_versions": {
    "daily_nssi_ema": "1.0",
    "weekly_nssi": "1.0"
  },
  "daily_core": {},
  "conditional_details": {},
  "weekly_extension": {},
  "derived_metrics": {},
  "completion": {},
  "safety_signals": {},
  "recording": {},
  "upload": {}
}
```

条件跳过使用显式状态 `not_applicable`，未作答使用 `missing`。两者均不能替换为 0。

### 9.3 保存与上传顺序

```text
完成录像
-> 填写并逐步保存问卷草稿
-> 校验并原子写入正式 JSON
-> 上传 JSON
-> 上传录像
-> 两者均成功后允许清理本地副本
```

JSON 使用临时文件加原子替换写入。刷新或网络中断后，通过 `record_id` 恢复草稿。

同一受试者同一天只创建一条正式记录。已提交记录需要更正时创建新修订，保留 `revision` 和被替代记录信息，不原地覆盖。

远端路径使用稳定记录目录：

```text
<SAVE_DIR>/<subject_id>/<YYYYMMDD>/<record_id>/
```

重试使用相同远端路径和文件名，避免重复数据。

## 10. 错误处理

- 必答题未完成时不允许正式提交，并定位到首个缺失问题。
- 条件分支只在触发条件满足时要求作答。
- 每周扩展未完成时整条记录标记为 `incomplete`，不计算相应量表总分。
- 页面刷新、浏览器短时断开或 Streamlit 重跑后恢复当前步骤和草稿。
- JSON 上传失败时不删除 JSON 或录像。
- 录像上传失败时保留录像并提供同记录重试。
- 只有 JSON 与录像均确认上传成功后才能执行本地清理。
- 转码失败时保留原始有效录像并记录媒体格式，不阻断问卷保存。
- 错误不能被空 `except` 静默吞掉；受试者看到可恢复提示，研究日志保存技术详情。

## 11. 测试与验收

### 11.1 计分测试

- SICQ 第 7 题反向计分正确，总分边界为 0 和 28。
- 改变准备度三项保持独立。
- 行为类型实际次数正确求和。
- `missing` 与 `not_applicable` 不参与计分。
- 正式 DSHI-Y 与日级实际次数使用不同字段和指标标识。

### 11.2 分支与日历测试

- 三个核心是/否问题分别触发正确分支。
- 阴性回答不生成伪 0 分追问。
- 第 7、14、21、28 天追加且只追加一次每周扩展。
- 其他干预日不显示每周扩展。
- 同日重新进入恢复原记录，不生成新记录。
- 修订已提交记录时保留审计链。

### 11.3 持久化与上传测试

- Streamlit 重跑、刷新和模拟中断后草稿可恢复。
- JSON 与录像共享相同 `record_id`。
- JSON 上传失败、录像上传失败和转码失败均可恢复。
- 任一上传失败时本地文件不被删除。
- 两个文件成功后才触发清理。

### 11.4 界面测试

- 正常日 5 个核心问题目标用时不超过 2 分钟。
- 受试者端不出现得分、风险等级、远端路径或运维信息。
- 桌面与移动端无文字截断、控件重叠和横向滚动。
- 滑动条支持触摸、鼠标和键盘，端点语义清晰。
- 200% 浏览器缩放下仍能完成全部操作。
- Alto 参考配色保持可读对比度，颜色不是状态含义的唯一载体。

## 12. 本轮不包含

- 受试者端与管理员端的完整权限隔离。
- 自动风险分级、通知研究人员和临床升级流程。
- 研究后台趋势图、管理仪表盘或跨受试者分析。
- 数据库迁移。
- 除问卷模块外的完整网站视觉重构。

上述内容按既定顺序在问卷功能完成后进入下一轮：先处理角色隔离、路径与数据可靠性、风险响应，再进行整体页面视觉和交互重构。
